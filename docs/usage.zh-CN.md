## 记录

在微信的 **“微信 ClawBot”** 对话里（建议置顶）：

- **文字 / 语音**：每条存成一篇独立笔记，例如 `00-收件箱/2026-10-27 0915 注意力本质是加权求和.md`。语音由微信自动转成文字，机器人回复里会附上识别结果，方便核对
- **带标签自动归档**：`#工作`、`#英语`、`#AI`、`#踩坑`，或者用 `工作：`、`踩坑：` 开头。全角 `＃`、大小写、标签后直接接中文都能识别
- **图片 / 文件**：保存到 `00-收件箱/附件/`，生成一篇带链接的笔记，在 Obsidian 里能直接看到
- **引用**：长按之前的消息 → 引用 → 写想法，笔记里会同时保存原文
- 只有扫码绑定的那个微信能写入，别人发来的消息会被忽略

## 在微信里查看和修改笔记

微信不支持可点击的按钮，所以用“编号列表 + 回复数字”来操作：

- `/目录`：列出知识库，回复数字进入文件夹或打开笔记；`/上级` 返回
- `/搜 关键词`、`/最近`：快速找到笔记；`/下一页`、`/上一页` 翻页
- 打开笔记后：`/追加 内容`（只发 `/追加` 的话，下一条文字或语音就是追加内容）、`/改写`、`/替换 旧=>新`、`/重命名 新名称`、`/移动`、`/删除`
- `/今天` 查看今天记了什么，`/撤销` 删掉刚存的那条，`/帮助`、`/帮助 浏览` 查看说明

所有指令都有英文别名，见 [English usage](usage.en.md#commands)。

**安全措施**：笔记打开后，如果被其他设备改过，修改会被拒绝（发 `/看` 重新打开即可）；删除的笔记放进知识库里的 `.trash` 回收站，不会真正删除。

## 和多设备同步的配合

多台设备之间用 Self-hosted LiveSync 同步，数据库跑在 Mac mini 上（搭建方法见[搭建全记录](guide.zh-CN.md#六搭建步骤)）。Mac mini 上的 Obsidian 需要一直开着，机器人新建的笔记由它推送给其他设备。

**机器人只新建笔记，从不修改已有笔记**，所以收件箱里的内容你随时可以在任何设备上编辑、改名、移动、合并，不会和机器人冲突。唯一要避免的是两台设备同时改同一篇笔记。

**想按天浏览收件箱？** 安装社区插件 Dataview，新建一篇 `收件箱总览.md`：

````markdown
```dataview
TABLE WITHOUT ID file.link AS 记录, author AS 来自, type AS 类型
FROM "00-收件箱"
SORT created DESC
GROUP BY dateformat(created, "yyyy-MM-dd") AS 日期
```
````

## 自定义归档规则

编辑 `config.toml` 里的 `[[routes]]`，比如加一个“读书”：

```toml
[[routes]]
name = "读书"
tag = "#读书"
dir = "01-学习/读书"
```

改完运行 `./install.sh` 重启生效。

## 备份、巡检、告警

- **告警邮箱**：在 `config.toml` 的 `[alert]` 里填 `email` 和 `auth_code`（QQ 邮箱授权码，不是 QQ 密码），运行 `.venv/bin/python monitor.py --test-email` 测试。其他邮箱也可以，改 `smtp_host`、`smtp_port` 即可
- **巡检**（每 30 分钟）：检查机器人、同步数据库、Tailscale（含密钥过期）、Obsidian、硬盘空间、备份。能自愈的先自愈，修不好的发邮件；同一问题 12 小时内不重复发，恢复后再发一封“已恢复”
- **日报**：每天 8 点后发一封。哪天没收到，说明 Mac mini 可能整机宕机或断网了
- **备份**：每天 3 点后打包到 `~/kb-backups`，保留 30 天。恢复时解压对应日期的压缩包即可
- **微信会话失效**：先按官方做法暂停 1 小时自动重试；仍然失效就把登录二维码发到邮箱。用电脑打开邮件扫码，或者在手机上长按二维码“识别图中二维码”。也可以通过屏幕共享在终端运行 `bot.py --login`，机器人会自动换用新凭证

以上时间、天数、阈值都可以在 `config.toml` 的 `[backup]`、`[monitor]` 里修改。

## 常用命令

在程序所在的文件夹里运行（例如 `~/wechat-obsidian-inbox`）：

| 想做的事 | 命令 |
|---|---|
| 查看机器人日志 | `tail -f ~/Library/Logs/kb-wecom-bot.log` |
| 查看巡检日志 | `tail -f ~/Library/Logs/kb-monitor.log` |
| 改配置后重启 | `./install.sh` |
| 检查配置 | `.venv/bin/python bot.py --check` |
| 立即巡检（只看不修） | `.venv/bin/python monitor.py --check` |
| 立即备份 / 发日报 | `.venv/bin/python monitor.py --backup` / `--report` |
| 测试告警邮件 | `.venv/bin/python monitor.py --test-email` |
| 重新扫码绑定微信 | `.venv/bin/python bot.py --login` |
| 停止并取消开机自启 | `./uninstall.sh` |
| 离线自测（不需要任何账号） | `.venv/bin/python tests/selftest_ops.py`，以及 `selftest_browse.py`、`selftest_weixin.py`、`selftest.py`（运维测试需要先 `pip install aiosmtpd`） |

## 排错

| 现象 | 处理 |
|---|---|
| 机器人没反应 | 看日志里有没有“✅ 已连接微信” |
| 日志显示“微信会话失效（errcode -14）” | 先等一等，会自动重试；需要扫码时二维码会发到邮箱。也可以运行 `bot.py --login`，无需重启 |
| 日志显示“证书验证失败” | 代理或 VPN 软件可能在拦截 HTTPS，把 `*.weixin.qq.com` 设为直连 |
| “知识库无法写入” | 知识库放在了文稿、桌面或 iCloud 里，挪到用户主目录下 |
| 图片或文件保存失败 | 下载链接只有 5 分钟有效，网络慢时可能失败，重新发送即可 |
| Obsidian 同步失败（开着代理） | 见[踩坑记录第 5 条](guide.zh-CN.md#八踩坑记录) |
| （企业微信通道）“订阅失败” | Bot ID 或 Secret 填错，或者机器人没选“长连接” |
| （企业微信通道）反复“被新的连接顶掉” | 同一个机器人只能有一个连接，检查是否在别的电脑上也运行了本程序 |

## 企业微信通道（可选）

程序也支持企业微信“智能机器人”（API 模式，长连接）：把 `config.toml` 里的 `channel` 改成 `"wecom"`，并在 `[wecom]` 里填写 Bot ID 和 Secret。注意：企业微信智能机器人**只能在企业微信 App 里使用**。
